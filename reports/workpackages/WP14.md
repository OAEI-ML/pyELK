## 0.2.0 model/schema migration addendum — 2026-08-02

The production migration moves pyELK's shared boundary to `pyowl-core>=0.2,<0.3`, API `(0, 2)`,
model schema 2, wire `(1, >=2)`, adapter protocol 1, and structural-columns schema 2. Python and
Rust consumers validate the frozen schema-2 descriptor, v2 structural and semantic fingerprint
domains, owner fingerprint schemas, recursive segment schemas, and component/occurrence anonymous
scope remaps before compiling. Schema 1 is not reinterpreted under model schema 2.

Scalar Python and scalar-wire Rust remain complete when the capability is absent. Once a provider
advertises schema 2, a malformed descriptor, fingerprint, owner, or segment fails closed before
session publication and cannot trigger scalar fallback. The package, workflows, artifact auditor,
SBOM generator, and installed contract all require the 0.2 core line. Historical 0.1.x evidence
below remains immutable; 0.2.0 supply-chain evidence is generated in its own directory.

The release ledger binds both `tested_source` and `native_ontology_redesign` to pyowl-core 0.2.0
commit `2fc1004c841ba968183ca0cccdcf7ee298ae4bc7`, tree
`8ef0c1e9714d4b71ae1483ad58162ee1903cdbe6`. The matching supply-chain constants and tests require
that exact source identity, and `reports/release/0.2.0` is regenerated from it rather than
inferring compatibility from a package version.

## Outcome

pyELK now contains the complete repository-owned encoded structural ingestion path behind an
empty capability ledger. It validates the frozen structural-columns v1 envelope and all eleven
read-only columns, compiles the full scalar-supported ELK constructor surface directly into
Rust-owned IR, constructs the permanent native session without private-IR serialization, and
retains every required owner until close. Direct, decoded/indexed, mmap, selected overlay,
base-plus-delta overlay, direct composite, recursive composite, and nested anonymous-scope
composition paths have exact scalar compiler/result comparisons.

Unsupported constructs remain transactional whole-axiom decisions with the exact scalar feature
counts; there is no per-row callback or semantic fallback after encoded handoff. Scalar Python and
scalar-wire Rust remain complete when capability negotiation returns no handoff. Public
`Reasoner.diagnostics()` now publishes a sorted immutable, path-safe compiler handoff containing
the canonical digest, compiler/IR schema versions, implementation/native ABI, consumer compile
time, encoded-view publication time where applicable, scalar materialization rows, and the exact
encoded ownership/copy/segment ledger. Recursive composite staging reports four bytes per
resolved root posting and 64 bytes per anonymous-scope digest pair.

This is not pyELK capability promotion or WP14 release acceptance. pyELK's native
`encoded_view_schemas()` deliberately remains empty, so ordinary backend negotiation still uses
the scalar-wire production boundary. The pyowl-core prerequisite is no longer empty:
structural-columns v1 is frozen and advertised, and `a909cfc` exercises that public handoff while
preserving pyELK's fail-closed promotion boundary.

## Acceptance blockers

1. **Released core range and promotion review — pyowl-core/pyELK owners.** The current core
   advertises structural-columns v1 and the local installed public-handoff matrix passes. pyELK
   still needs the reviewed released core range plus the remaining evidence below before its own
   capability can be advertised. Neither package may infer compatibility from package versions or
   private bindings.
2. **Gate-eligible performance evidence — labelled runner/corpus owner.** Run the real advertised
   producer through direct, mmap, overlay, and composite workloads plus the full generated and
   hash-pinned biomedical corpus with two warm-ups and five measured samples. The report must pass
   exact compiler/result parity, zero parser/resolver/wire/scalar materialization and base
   flattening, at least 2x encoded view-to-result geometric-mean speedup, a boundary fraction below
   5%, and the 10% per-workload time/RSS guardrails.
3. **Same-machine Java/release baseline — release owner.** Attach the pinned ELK 0.6.0 comparison
   from the same machine and satisfy the existing Java-relative and prior-release thresholds. A
   smoke report, unrelated hardware, or the experimental scalar producer cannot substitute.
4. **Installed native artifact matrix — release CI.** Rebuild and test tier-one ABI3 wheels across
   supported platforms/interpreters with the advertised core, forced Python and Rust selections,
   pure-wheel/sdist fallback, sanitizers/fuzz where prescribed, dependency/linkage, SBOM/licence,
   no-Java, and Python-source equality audits.
5. **Final consumer revisions — Exact/OAEI owners.** Repeat the shared-view/composite identity and
   bounded handoff checks against clean pinned Exact-OM and OAEI revisions after core promotion;
   record those revisions without adding a runtime dependency cycle.

Until all five blockers close, documentation and backend reports must call encoded ingestion an
experimental hidden implementation, `encoded_view_schemas` must remain empty, and `auto` must not
select it from an advertised capability.

## Handoff

Dependent work may rely on scalar semantics, the compiler digest/schema meaning, exact public
diagnostic field names, structural-columns v1 validation, and the hidden test seam. It may not rely
on a package-version guess, private pyowl-core extension import, schema-local ID persistence, or
the availability of encoded ingestion in an installed environment.

WP14 closes only when the final released core/consumer revisions are frozen, the gate-eligible
performance and supported-platform installed-artifact matrices pass, pyELK's capability is
explicitly promoted, and the resulting revisions and machine-labelled evidence are appended to
this report.
